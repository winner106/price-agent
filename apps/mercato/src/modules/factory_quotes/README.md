# 工厂报价：手工纵切

本模块是 Open Mercato 工作副本中的增量实现，不是完整 Agent，也未达到上线试点验收。请先在隔离环境用虚构资料验证，勿把生产报价或业务图纸录入未验证的部署。

## 入口与数据

- `/backend/factory_quotes`：模板、询价、当前试算、岗位确认、独立审批、正式打印、结果和实绩登记。选择记录后可用 `?id=<uuid>` 恢复已保存的记录。未点击保存的本地表单不会持久化。
- `GET /api/factory-quotes`：当前组织的可见列表与操作能力。`?id=<uuid>` 读取组织内单据的字段投影。共享边界是**选定组织内获授模块权限的报价组**，没有单据成员级 ACL；私人笔记仅作者可读。没有匿名端点和客户门户。
- `POST /api/factory-quotes`：通过 Open Mercato 请求会话、权限、变更守卫及命令总线执行动作。负载包含 `id`、`revision`、`token`、`action`。新建用 `revision: -1`，其他动作使用最新修订号。重复请求使用同一 token 和负载；修改后使用新 token。出现 `409` 应当重新读取再决定，不自动覆盖。
- MikroORM 迁移创建 `factory_quote_records`（租户、组织、修订及业务状态）和 `factory_quote_events`（动作、操作者、去重 token、快照及时间）。模板及报价发布后不可原地更改；新模板从旧模板复制，已发布报价不能直接产生关联修订单。暂不写入 Sales Quote、ERP 或外部系统。
- 规则只接受按批、按件、准备工时、单件工时组件；来源与有效日期人工维护在本次报价。金额输入为十进制字符串，计算用 BigInt 固定小数与整数比，最终显示保留两位；收益率门槛比较不使用展示舍入。未知成本和零值区别对待。日期校验当前取 UTC 日期。

## 初始化与验证环境

使用原仓库的 Linux 部署方式（Node.js 24、仓库指定 Yarn 4、PostgreSQL 15+、按需 Redis/Meilisearch）。**不要使用 Cloudflare Pages 或 Genspark 一键 Hosted Deploy**。

1. 按根 README 和 `apps/mercato/.env.example` 在宿主环境配置独立测试数据库、会话签名秘密及数据库凭据。用部署秘密配置 `OM_INIT_SUPERADMIN_EMAIL` 和强密码 `OM_INIT_SUPERADMIN_PASSWORD`，不提交真实凭据。首次初始化用原平台的管理员账号字段，尚不支持无邮箱、中文账号或工号登录。
2. 在仓库根目录执行 `yarn install --immutable`，然后用仓库的 `yarn build:packages` → `yarn generate` → `yarn build:packages`。空数据库初始化用 `yarn workspace @open-mercato/app initialize --no-examples --no-demo-users`。已有测试数据库先做备份，并按平台流程经负责人批准后执行 `yarn db:migrate`；不要用初始化重装覆盖数据库。
3. 旧租户角色可按平台流程同步默认 ACL：`yarn workspace @open-mercato/app mercato auth sync-role-acls`。注册新页面后按平台流程刷新结构缓存：`yarn workspace @open-mercato/app mercato configs cache structural --all-tenants`。构建 `yarn build:app` 并按现有服务运行方式启动；本次未部署。测试部署必须限制为内网或受控入口，并检查平台其他模块的登录/注册设置；本模块未更改全局注册行为。
4. 本模块暂不接模型、没有 Key 表单，也不会把任何报价内容发送给模型。CSV 请求只持久化预览和导入审计，不保存原始文件。没有附件持久卷或报价定时任务代码，不能上传参考图纸或自动提醒。切勿为了演示而开启别的 AI 路由来发送本单内部信息。

## 岗位权限

用平台的角色编辑器为组织下的普通员工赋权，一人可多岗。每个使用者需 `factory_quotes.view`。`configure` 编辑并试算模板，`publish_template` 确认模板发布；`edit` 填写报价和送审。`technical` 确认工艺、`cost` 查看/维护/确认成本、`delivery` 确认交期并可注明实际线下确认方、`approve` 独立审批、`release` 正式发布，`review` 与 `cost` 共同用于登记实绩。敏感岗位使用**明确功能授权**，不要依赖全局通配符。管理员默认配置权限不等于查成本或审批权限。至少准备两名不同员工，且审批人不能与提交人相同。

## 手工走查脚本（不是已完成的端到端测试）

1. 配置员从「创建机加工模板草稿」开始，修改名称、字段单位、委外条件或品牌色；保存后运行虚构样本，授权配置发布者确认发布。也可从 SKU 种子手动创建售价和每件采购成本依据；它并非自动协议价或阶梯价格。
2. 报价员选择发布模板创建询价，把虚构邮件要点粘到私人笔记，选择 `samples/machining.csv` 预览，确认列映射和数据行后导入。没有成本权限的员工不能映射工时等私有字段。`samples/machining.xlsx` 有两张表并保留料号前导零，但 XLSX 仍只能作为手工参考。分别填期望日期和拟承诺交期，同时填交付地点、付款、运费范围、税和有效期。
3. 已授权成本员工为材料、准备、加工、委外、包装物流分别录入 120、300、40、600、1200；每项给出虚构出处及覆盖当前日期的有效期。技术、成本、交期分别确认。此时 600 件，总成本 ¥86,400（单件 ¥144），未税售价 ¥110,400（单件 ¥184），收益 ¥24,000，展示收益率 21.74%。
4. 送审，另一名员工核准，由授权发布者正式发布。点击「生成打印版」，再用浏览器打印为 PDF。员工自行外发并登记；系统不自动外发。尝试修改已发布报价、或让提交者自批，均应拒绝。
5. 记录成交，录入实际 580 件，实绩总成本 ¥87,000 和来源；应看到单位成本偏差 +¥6，正式报价不变。

## CSV 导入与重试

- 只导入当前草稿报价项。先预览最多 5 行，核对表头、列映射和物理数据行范围后确认。表头冲突不会自动绑定；未映射售价暂置为 0，仍会阻塞正式发布。已有项不覆盖，初始空占位项会替换；导入后费率及岗位确认需重新核定。
- CSV 支持 UTF-8、BOM、CRLF、引号及引号内换行。限制 10 MiB、最多 100 列、表头后 10,000 非空数据行，每张报价仍最多 50 项。选中单元格任何一条无效都不会部分提交；错误只返回行列坐标与错误码。
- 接口：`POST /api/factory-quotes`，`Content-Type: text/csv`，文件字节为请求体。`x-factory-csv` 传 JSON `{id,token,revision,headerRow,templateId}`。获取 `receipt` 后用相同原始文件和同一报价修订提交，元数据增加 `apply:{receipt,mapping,from,to}`，列位置从 1 开始。预览与操作者、组织、询价、模板、修订和 SHA-256 摘要绑定，有效期 30 分钟。
- 预览记录和导入事件沿用现有报价事件表，无新增迁移。导入审计保存映射、文件摘要、行号和选中原文；异步或网络重试用同一请求 token，且同一文件、表头、范围和映射不能在本单重复追加。不对重叠范围或不同文件做业务去重。

## 相似历史报价

在当前询价选择一个已保存的报价项，点击「查找相似单」。`GET /api/factory-quotes?id=<uuid>&similar=<1-based-line>` 在当前租户和组织内检索最近更新的最多 150 份已发布报价，最多展示 8 条历史报价项。按公开的料号、图号、材料、同维度尺寸、工艺字段和批量比较，显示匹配依据、差异、来源单据、模板版本和发布时间。未提供的单边条件显示待核实；数量相同不会单独构成匹配。此检索不读草稿历史，不返回客户名称、内部成本、费率或成本依据，不写回当前单据。历史未税售价仅供参考。

## 验证结果及上线前缺口

- Linux、Node 24.16.0 下使用 `yarn install --immutable --mode=skip-build` 完成锁定依赖链接。标准仓库命令 `yarn workspace @open-mercato/app test --runInBand src/modules/factory_quotes/__tests__` 的 3 个套件、15 个用例通过，含 CSV 解析、保护映射及模拟事务内重复导入、过期修订和跨组织拒绝。模拟事务不是 PostgreSQL 集成测试。`yarn build:packages` 在核心包因 esbuild 服务停止失败；完整注册表生成、应用构建、全应用迁移、浏览器及部署仍未验证。
- PostgreSQL 17.12 隔离测试：设置 `FACTORY_QUOTES_TEST_DATABASE_URL` 为仅本地测试实例的连接串，再运行上面的 Jest 命令。测试只接受回环地址，创建随机独立 schema，经 MikroORM 执行本模块迁移，并在结束时删除该 schema。不设变量时跳过这一套件。已实测 **5 个套件、18 个用例通过**：通过报价 GET/POST 处理器和真实数据库执行模板发布、并发 CSV 重试（只保存一条导入事件）、岗位确认、独立审批、正式输出及成交复盘。已核对跨租户/组织读拒绝、只读员工不能发布、正式输出不含成本出处、复盘不改变正式快照、跨组织相似单查询被拒绝、相似单不回填价格或成本。测试注入的是会话、权限数据和命令总线适配器，不覆盖完整的 Open Mercato 会话、部署或浏览器栈。
- 无真实供应商验证、无真实试点样本；不能把领域测试当作准确率或拦截率实测。试点应记录：字段提取准确率＝经工程师核定正确候选值/抽检候选；计价一致性＝同口径双算完全一致单数/双算总单数；关键错误拦截率＝被阻塞的已标注关键错误/所有注入及实测关键错误；人工修改次数按业务动作审计逐单计数；耗时从询价接收到正式发布，单列外部等待。五项均未实测，没有达标声明。
- 上线前必须补齐：双入口 AI SDK/useChat 与只写密钥；行业集合、方案与模板/品牌独立版本；受权附件和 XLSX 解析与导入；主数据契约、SKU 阶梯/协议价和冲突；细粒度单据权限、站内任务、去重通知及调度；跨租户/并发/端到端验证。当前手工策略使用通用例外标记，不能覆盖完整底价、付款和交付策略。不要将这份代码当作完整试点交付。
